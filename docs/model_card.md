# Model Card — Credit-Card Default Predictor

| Field                     | Value                                                      |
|---------------------------|------------------------------------------------------------|
| **Model name**            | `gbt` (production), `logreg_l1`, `logreg_l2` (challengers) |
| **Model type**            | Binary classification (default vs. non-default)            |
| **Algorithm (production)**| `HistGradientBoostingClassifier` (`max_depth=6`, `lr=0.05`, 300 trees, L2=1.0) |

## 2. Intended use

- Predict the probability that a consumer credit-card account charges off
  over a fixed horizon.
- Portfolio-level use: input to loss forecasts, capital reserve modeling,
  and stress-scenario planning.
- Account-level use: risk ranking for account management (limit changes,
  early-warning treatment queues).
- **Not intended** for adverse-action credit decisions without additional
  fairness testing, reason-code generation, and regulatory review (ECOA,
  Reg B, FCRA).

## 3. Training data

- **Source**: synthetic dataset generated by `src/generate_synthetic_data.py`,
  simulating 500,000 consumer credit-card accounts spanning origination
  vintages 2018–2023.
- **Split**: time-based. Train = vintages 2018–2021 (333k rows), test =
  vintages 2022–2023 (167k rows).
- **Class balance**: ~15.1 % positive (charge-off) rate.
- **In production**, this would be replaced with internal account-level
  data pulled from the servicing warehouse.

## 4. Features (23 numeric + 4 categorical)

Numeric: `age`, `income`, `employment_length`, `fico`, `utilization`,
`total_tradelines`, `inquiries_6m`, `credit_limit`, `current_balance`,
`months_on_book`, `apr`, `payment_ratio`, `dpd_30_last_12m`,
`dpd_60_last_12m`, `dpd_90_last_12m`, `purchase_volume_3m`,
`payment_to_balance`, `balance_to_limit`, `dpd_severity`,
`income_to_limit`, `spend_to_limit`, `vintage_avg_dpd30`,
`vintage_avg_utilization`.

Categorical: `state`, `utilization_bucket`, `fico_bucket`, `months_on_book_bucket`.

## 5. Performance

Time-based hold-out (167k accounts, vintages 2022–2023):

| Model     | AUC   | Gini  | KS    |
|-----------|-------|-------|-------|
| LogReg-L1 | 0.744 | 0.487 | 0.361 |
| LogReg-L2 | 0.744 | 0.487 | 0.361 |
| **GBT**   | 0.742 | 0.484 | 0.358 |

Discrimination is roughly equivalent across model families here because
the underlying data-generating process is close to linear; on a real
portfolio the gradient-boosted model is expected to widen the gap.

## 6. Assumptions

- Feature definitions match those documented in `README.md`.
- Charge-off definition is consistent with servicing policy over the observation window.
- Population is broadly comparable to training vintages (see PSI monitor).
- No time-series or panel structure beyond the vintage-level rollups.

## 7. Limitations

- Trained on synthetic data with known linear structure; the reported
  metrics are proof-of-concept, not benchmarks for production.
- No macroeconomic covariates in the model itself — those are applied
  only in the stress-scenario post-processing step.
- Categorical features are one-hot encoded; high-cardinality fields
  (e.g., ZIP) are not currently supported.
- Class threshold defaults to 0.5; the operating threshold should be
  chosen based on business cost-of-false-positive vs. cost-of-miss.
- No fairness testing yet across protected classes.

## 8. Model governance controls

- **Version control**: source code committed to git; model artifacts
  pickled with SHA in filename in production.
- **Reproducibility**: fixed random seed (`RNG=42`); pipeline can be
  re-run end-to-end with `run_all.sh`.
- **Monitoring**: `monitor_drift.py` computes PSI for every input
  feature and for the model score itself. Bands: <0.10 no shift,
  0.10–0.25 investigate, >0.25 retrain.
- **Stress testing**: `stress_scenarios.py` evaluates 12 baseline and
  adverse macroeconomic scenarios covering unemployment, FICO drift,
  income shocks, and delinquency shocks.
- **Documentation**: this model card + README + inline docstrings.

## 9. Ethical considerations

- Model uses `income` and geographic (`state`) features that can correlate
  with protected characteristics. Before any lending-decision use, fair-lending
  testing (disparate impact, adverse-action reasons) is required.
- Score outputs are probabilities, not certainties; downstream systems
  should not treat any single account as definitively "will default."
